## Overview

Pactus Blockchain [Version 1.17.0 (Berlin)](https://github.com/pactus-project/pactus/releases/tag/v1.17.0)
is now available for download.
This release includes the following applications:

- [Pactus GUI](https://docs.pactus.org/get-started/pactus-gui/):
  The graphical user interface (GUI) for the Pactus node that is suitable
  for both beginners and experienced users.

- [Pactus Daemon](https://docs.pactus.org/get-started/pactus-daemon/):
  The command-line interface (CLI) for the Pactus node that is suitable for experienced users.

- [Pactus Shell](https://docs.pactus.org/tutorials/pactus-shell/):
  The command-line tool that allows users to interact with a Pactus node.

- [Pactus Wallet](https://docs.pactus.org/tutorials/pactus-wallet/):
  The wallet software that allows users to manage their wallet and send transactions
  without the need to sync the entire blockchain.

## Highlights

The most significant change in the Berlin release is the implementation of **Native State Anchoring**,
introduced through Pactus Improvement Proposal 50 ([PIP-50](https://pips.pactus.org/PIPs/pip-50)).
This adds a single live, deposit-backed commitment slot to each Pactus account, enabling
off-chain applications such as document stamping, DID documents, revocation registries,
and service manifests to attest to a bounded digest directly in the account state.

An anchor lives in the current global state, so a pruned node can still serve it without
the historical transaction that created it, and it can be revoked by deleting the slot,
which refunds the deposit. A create and an update require a refundable deposit of at least
`1 PAC`, and the protocol-written timestamps come from the including block, never from the
transaction payload, so they cannot be forged. Consensus stores no application payloads,
files, or search indexes; those remain off-chain.

Together with the new payload type and the extended account serialization, the official node
exposes read, build-transaction, and change-notification APIs (`GetAnchor`, `ListAnchors`,
`GetRawAnchorTransaction`, and the `anchor_info` ZMQ topic) so wallets, indexers, and apps do
not need to invent a parallel convention. As with every protocol change, this feature is
activated through [PIP-51](https://pips.pactus.org/PIPs/pip-51) at protocol version **5**,
once more than 75% of committee power supports it.

The GUI has received a complete visual overhaul. The modernized GTK interface introduces a
sidebar navigation, redesigned node and validator dashboards, and full **light and dark theme**
support, giving the application a cleaner and more consistent look on every platform.

![Pactus GUI]({{<image "pactus-gui-new-look.png">}})

Alongside the new look, the GUI replaces emoji with crisp SVG icons, shows transaction time and
pager arrows in transaction lists, adds balance and stake to address lists, adds a **Max** button
to amount fields, and can optionally start automatically on system startup.

Legacy JSON wallets can now be migrated to the modern SQLite storage. The migration is available
from the GTK GUI with a dedicated upgrade button, through a new `migrate` command in the CLI,
and over a new `MigrateWallet` gRPC endpoint, so existing users can move their wallets in place
without losing funds.

On the protocol and security side, secp256k1 account restrictions are removed after protocol
version 4, delegated withdrawals now require the stake owner's signature, CP quorum certificates
are bound to vote height and round, and subsidy transactions are rejected by the transaction pool.
Under the hood, the release includes a faster `CanVote` check with O(1) map lookups and a number
of stability fixes across the node, store, and sync.

## Download

To start using Pactus blockchain, download the latest version from the [download](/download)
page and join the Mainnet.

## How to Upgrade

If you are running an older version, close it first.
Then uninstall the previous version and install the newer version.
If you are using the archived version, simply replace it with the new version.
